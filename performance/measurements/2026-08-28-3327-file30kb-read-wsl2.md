## Workload
- Operation: Reading back 30 KB files (analogous to the corresponding write)
- Location: native
- Tool: bash `cat` to `/dev/null` (`../scripts/file30kb-read.sh`)
- Mode: sequential
- Window: 20 s
- Scale: 100,281 reads total across the 5 runs, against the 87,858-file (~2.7 GB) tree created by
  `2026-08-28-3327-file30kb-create-wsl2.md` immediately before this run.
- Content: 30 KB, unique per file (as created)

## Notes

First WSL2 file-content read measurement on `3327` at this size. Tightest spread of any workload
in this batch (981-1029, ~5% band) - the whole 2.7 GB working set fits comfortably in this
machine's RAM (32 GB per `../machines.md`), so every run reads an already page-cache-warm tree.

Reads run slightly ahead of creates at this size (1002.4 vs. 878.0 ops/s, ~14% faster) - a much
smaller read-ahead-of-create margin than `julius` shows for the same size (531.4 vs. 93.6 ops/s,
~5.7x), and the opposite of what native Windows on this machine shows at 10 MB (reads *behind*
creates once the working set exceeds cache, see `2026-08-28-3327-file10mb-read-native.md`) - at
30 KB this machine's create side is apparently still per-call-overhead-bound rather than
IO-bound, so cache-warm reads gain relatively little over it.
