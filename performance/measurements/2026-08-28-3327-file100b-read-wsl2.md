- Location: native

- Scale: 95,880 reads total across the 5 runs, against the 95,457-file tree created by

## Notes

First WSL2 file-content read measurement on `3327` at this size. Run 1 is close to the runs-2-5
median (~970.5), no warmup pattern - kept. No monotonic trend, unlike the matching create
measurement above; the spread (901-1019) is noise-sized on this non-isolated machine rather than a
systematic effect.

Reads run only slightly above creates at this size (958.4 vs. 954.0 ops/s) - unlike `julius`,
where reads clearly outpaced creates (603.4 vs. 107.0 ops/s), and unlike native Windows on this
same machine (page-cache-warm reads several times faster than creates, see
`2026-08-28-3327-file100b-read-native.md`'s Notes). Consistent with the create-side finding above
that per-call overhead (there: `perf-gen`'s process spawn; here: the read syscall plus this
script's own `cat` process spawn) dominates over actual content size at 100 B on this machine's
WSL2 side, for both directions.

Roughly 1.6x `julius`'s own WSL2 read result at this size (958.4 vs. 603.4 ops/s, see
`2026-08-28-julius-file100b-read-wsl2.md`) - a smaller ratio than the ~9x seen on the create side
above, plausibly because both machines' reads are similarly page-cache-warm here (working sets of
~9.5 MB on `3327` well under either machine's RAM) while creates are not equally comparable
(different underlying content-generation cost per machine, as noted on the create side).
