# Directory listing - native - 3327/WSL2 Ubuntu 24.04/local SSD

## Setup
- Date: 2026-08-28
- Machine: 3327
- Execution environment: WSL2, Ubuntu 24.04.4 LTS. Working directory `~/dedupfs-perf/listing` -
  WSL2's own native filesystem, not `/mnt/c/...`.
- Power profile: base scheme `aeeed979-846d-4e51-bb46-e7b4f140eb43` ("Thieme Energy Options", a
  custom/renamed Windows scheme, not one of the stock named profiles), AC power-mode overlay
  `961cc777-2547-4f9d-8174-7d86181b8a7a` = `OVERLAY_SCHEME_MIN` ("Besseres Overlay für
  Akkulaufzeit" / "Best power efficiency"). On AC power (plugged in), developer-confirmed at the
  start of this session.
- IO device: local SSD (WSL2's own ext4 virtual disk, backed by the host's NVMe SSD per
  `../machines.md`)
- DedupFS build: `deadac0e` on `rust-performance-test-idea` - native filesystem baseline, no
  DedupFS code exercised; recorded only to pin which script version was run.
- Isolation: none taken deliberately - ran as the sole foreground command in an otherwise idle
  WSL2 session; host-side background activity was not controlled or observed.

## Workload
- Operation: Directory listing (readdir)
- Location: native
- Tool: bash `ls -U`, one process per listing (`../scripts/dir-listing.sh`)
- Mode: sequential
- Window: 20 s
- Scale: fixed 50,000-entry directory under `~/dedupfs-perf/listing`, built once before this
  measurement; 5,740 listings total across the 5 runs.
- Content: n/a (directory listing, no file content)

## Notes

First WSL2 listing measurement anywhere in this project (`julius` has a WSL2 row too, but no
`3327` row existed yet). Extremely tight spread (56-58 across all 5 runs) - a fixed-size directory
with no growth, as expected.

Roughly 1.7x `julius`'s own WSL2 result (57.2 vs. 33.8 ops/s, see
`2026-08-28-julius-dir-listing-wsl2.md`) - a smaller machine-to-machine ratio than directory
lookup showed (~2x) above, consistent with this operation being dominated by per-entry work
inside a single `ls -U` process rather than by per-call syscall/process overhead, where a
faster CPU helps proportionally less.
