# 10 MB file creation - native - 3327/WSL2 Ubuntu 24.04/local SSD

## Setup
- Date: 2026-08-28
- Machine: 3327
- Execution environment: WSL2, Ubuntu 24.04.4 LTS. Working directory
  `~/dedupfs-perf/files10mb` - WSL2's own native filesystem.
- Power profile: base scheme `aeeed979-846d-4e51-bb46-e7b4f140eb43` ("Thieme Energy Options", a
  custom/renamed Windows scheme, not one of the stock named profiles), AC power-mode overlay
  `961cc777-2547-4f9d-8174-7d86181b8a7a` = `OVERLAY_SCHEME_MIN` ("Besseres Overlay für
  Akkulaufzeit" / "Best power efficiency"). On AC power (plugged in), developer-confirmed at the
  start of this session.
- IO device: local SSD (WSL2's own ext4 virtual disk, backed by the host's NVMe SSD per
  `../machines.md`). Free space on WSL2's virtual disk before this run: 745 GB available
  (`df -h ~`), no concern.
- DedupFS build: `deadac0e` on `rust-performance-test-idea` - native filesystem baseline, no
  DedupFS code exercised; recorded only to pin which script version was run.
- Isolation: none taken deliberately - ran as the sole foreground command in an otherwise idle
  WSL2 session; host-side background activity was not controlled or observed.

## Workload
- Operation: File creation at 10 MB, unique content
- Location: native
- Tool: bash redirection, content from `perf-gen` (`../scripts/file10mb-create.sh`)
- Mode: sequential
- Window: 20 s (standard, not reduced - ample free space on this machine)
- Scale: 5,250 files total across the 5 runs (947-1094 per run, time-boxed not count-fixed),
  spread round-robin across 20 subdirectories under `~/dedupfs-perf/files10mb`, first measurement
  against this tree. ~52.5 GB total written.
- Content: 10 MB, unique per file (`perf-gen`-generated)

## Notes

First WSL2 file-content measurement on `3327` at this size, and (unlike `julius`'s and `3327`'s
own native-Windows 10 MB runs) no window reduction was needed - 745 GB free comfortably absorbs
the ~52.5 GB this run wrote. Run 1 is close to the runs-2-5 median (52.5), no warmup outlier -
kept. Run 3's dip (47 ops/s) is the one notable outlier in an otherwise 52-54 band; not a
monotonic trend like `julius` shows at this size, and not investigated further on this
non-isolated machine.

Roughly 2.7x `julius`'s own WSL2 result for this workload (52.0 vs. 19.6 ops/s, see
`2026-08-28-julius-file10mb-create-wsl2.md`) - closer to the ~2.4-2.7x seen at 100 B/30 KB above
than to the smaller ratios earlier operations showed, plausibly because 10 MB is finally
write-volume-bound (~520 MB/s here) rather than per-call-bound, so raw NVMe-vs-SATA throughput
(per `../machines.md`) shows through more directly than at the smaller, call-overhead-dominated
sizes.
